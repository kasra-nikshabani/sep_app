# ADR-0009: Baseline Spring Boot، Build Tool، و Migration Tool

- **وضعیت:** پذیرفته‌شده (تأیید کارفرما، Phase 6)
- **تصمیم‌گیرندگان:** کارفرما + Architect

## Context

در تأیید اولیه‌ی پروژه (پیش از Phase 1)، «Java 21 + Spring Boot 3.3.x+» به‌عنوان یک پیشنهاد غیرقطعی مطرح و تأیید شد. در آغاز Phase 6 مشخص شد که از آن زمان Spring Boot یک نسخه‌ی اصلی کاملاً جدید (**4.x**، شروع‌شده از نوامبر ۲۰۲۵) هم منتشر کرده — یعنی «3.3.x+» دیگر به‌طور خودکار به معنای «جدیدترین» نیست. این یک تصمیم واقعی و باز بود که قبل از نوشتن اولین خط کد باید با کارفرما مطرح می‌شد (طبق بند ۲ بریف).

## Decision

### 1) نسخه‌ی Spring Boot: **3.5.x** (دقیقاً `3.5.16`، آخرین Patch این خط در لحظه‌ی نوشتن)

نه ۳٫۳ (قدیمی‌تر از آخرین گزینه‌ی پایدار همین خط) و نه ۴٫۱ (نسخه‌ی اصلی جدید).

### 2) ابزار Build: **Maven** (با Maven Wrapper، نه نصب سراسری سیستم)

### 3) ابزار Migration: **Flyway**

## Alternatives Considered

| تصمیم | گزینه‌ی رد‌شده | چرا رد شد |
|---|---|---|
| نسخه‌ی Spring Boot | 4.1.x (آخرین نسخه‌ی اصلی) | تغییرات شکننده‌ی قابل‌توجه نسبت به ۳.x: بازساختاردهی ماژول‌ها (نیاز به Starterهای صریح جدید مثل `spring-boot-starter-flyway`)، ارتقا به Jakarta EE 11/Servlet 6.1 (حذف Undertow)، مهاجرت کامل به Jackson 3 (تغییر Package از `com.fasterxml.jackson` به `tools.jackson`، تغییر `@JsonComponent`→`@JacksonComponent`)، و حذف کامل APIهای Deprecated (`@MockBean`/`@SpyBean` دیگر وجود ندارند). این یعنی الگوهای آشنا/اثبات‌شده‌ی من به‌عنوان دستیار کدنویسی کمتر قابل‌اتکا هستند و ریسک اشتباه‌های ظریف را بالا می‌برد — مستقیماً در تضاد با اولویت اول بریف (Correctness/Security). Spring خودش هم یک مسیر مهاجرت مستند از ۳.۵ به ۴.x ارائه کرده، پس این تصمیم قابل‌بازگشت و کم‌هزینه برای آینده است. |
| ابزار Build | Gradle (Kotlin DSL) | ساختار پروژه Single-module است (طبق ADR-0002، نه Multi-module)؛ در این حالت مزیت اصلی Gradle (Build افزایشی سریع‌تر در پروژه‌های بزرگ چندماژوله) کم‌رنگ می‌شود، درحالی‌که Maven برای خوانایی/Review توسط اعضای جدید تیم و هم‌راستایی با اکوسیستم غالب Spring Boot ساده‌تر است |
| ابزار Migration | Liquibase | Flyway برای الگوی SQL-native و Schema-per-module که در ADR-0007 انتخاب شد مستقیم‌تر است (هر Migration یک فایل SQL ساده، بدون لایه‌ی انتزاعی XML/YAML اضافه) |

## Consequences

- `backend/pom.xml` از `spring-boot-starter-parent:3.5.16` استفاده می‌کند.
- Maven Wrapper (`mvnw`, `.mvn/wrapper/`) به Repository اضافه شد تا نیازی به نصب سراسری Maven روی هیچ ماشین توسعه‌ای نباشد و نسخه‌ی Build دقیقاً Pin شود (`3.9.16`).
- این تصمیم در آینده (احتمالاً بعد از این‌که Spring Boot 4.x بالغ‌تر شد و تجربه‌ی عملی بیشتری از آن در دسترس بود) قابل بازبینی است؛ مسیر مهاجرت رسمی Spring از ۳.۵ مستند است.
